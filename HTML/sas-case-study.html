01. The Problem

Why Africa Needs Its Own Developer Platform

Every major developer social platform — Dev.to, Hashnode, Medium — is Western-centered. They're built around the lives, experiences, and cultural contexts of developers in the US and Europe. The tutorials, the success stories, the networking opportunities, even the writing prompts — they all assume a Western tech ecosystem.

For African developers, this creates a disconnect. We face unique challenges: unreliable internet, power outages, payment gateway limitations, and a job market that works differently. When an African developer writes about solving these problems on a Western platform, the audience often doesn't relate. The engagement is lower. The community is thinner.

I built SyntaxAndStories to change that. A platform where African developers can write about their real experiences, connect with peers who understand their context, and grow together — without being a footnote in someone else's tech narrative.

02. Architecture

System Design First

Before writing any code, I mapped out the entire data flow. The platform needed to handle real-time chat, a coin economy, social interactions, gravity-based content ranking, background tasks, and media processing — all while staying performant and secure.

Database Layer

PostgreSQL with a custom User model extending AbstractUser for maximum flexibility. User profiles, posts, comments, follows, blocks, reports, and coin transactions all live in normalized tables with proper indexing. Cloudinary handles media storage.

Real-Time Layer

WebSockets power the chat system for instant message delivery with rich link previews. Django Channels handles connection management, with Redis as the channel layer backend.

Economy Layer

A custom coin economy where users earn digital coins through engagement. All coin mutations use Django F() expressions wrapped in atomic transactions to eliminate race conditions. A separate Transaction model provides an immutable audit log.

Social Layer

AJAX-driven follow, like, comment, and block systems with no page reloads. The follow system uses a dedicated Follow model with unique_together constraints. The feed uses a gravity-based ranking algorithm balancing recency and engagement.

Cache & Status Layer

Redis serves dual duty: as the Channels layer backend for WebSockets and as a fast cache for online status tracking. User presence is stored in Redis with TTL expiration, enabling real-time "online now" indicators without hammering PostgreSQL.

Background Task Layer

Celery workers handle offline-heavy lifting: sending email notifications, processing link previews, cleaning up stale sessions, and batch-updating gravity feed scores. This keeps the request/response cycle fast and snappy.

models.py — Custom User Model 
from django.db import models, transaction
from django.contrib.auth.models import AbstractUser
from django.core.validators import FileExtensionValidator
from django.conf import settings
from decimal import Decimal

class User(AbstractUser):
    # Profile fields
    full_name = models.CharField(max_length=255, blank=True)
    bio = models.TextField(blank=True)
    location = models.CharField(max_length=200, blank=True)
    link = models.URLField(blank=True)
    skills = models.CharField(max_length=500, blank=True)
    
    # Media with validation
    profile_picture = models.ImageField(
        upload_to="profile_pictures/",
        blank=True, null=True,
        validators=[FileExtensionValidator(
            allowed_extensions=['jpg', 'jpeg', 'png']
        )]
    )

    # Social counters (denormalized for performance)
    follower_count = models.PositiveBigIntegerField(default=0, db_index=True)
    following_count = models.PositiveBigIntegerField(default=0, db_index=True)

    # Economy
    is_verified = models.BooleanField(default=False, db_index=True)
    is_premium = models.BooleanField(default=False, db_index=True)
    coin_balance = models.DecimalField(
        max_digits=10, decimal_places=2, default=0.00
    )

    def transfer_coins(self, receiver, amount):
        """Safely transfers coins using atomic transactions."""
        amount = Decimal(str(amount))
        if amount <= 0:
            return False, "Amount must be positive"
        if self.coin_balance < amount:
            return False, "Insufficient coin balance"
        if self == receiver:
            return False, "You cannot send coins to yourself"

        with transaction.atomic():
            self.coin_balance -= amount
            receiver.coin_balance += amount
            self.save()
            receiver.save()
        return True, f"Successfully sent {amount} coins"

    def save(self, *args, **kwargs):
        """Auto-downscale profile images to save Cloudinary space."""
        new_picture = False
        try:
            if self.id:
                this = User.objects.get(id=self.id)
                if this.profile_picture != self.profile_picture:
                    new_picture = True
            else:
                new_picture = True
        except User.DoesNotExist:
            new_picture = True

        if new_picture and self.profile_picture:
            from PIL import Image
            from io import BytesIO
            from django.core.files.base import ContentFile
            import os

            img = Image.open(self.profile_picture)
            if img.mode != 'RGB':
                img = img.convert('RGB')

            img.thumbnail((300, 300), Image.LANCZOS)
            output = BytesIO()
            img.save(output, format='JPEG', quality=60, optimize=True)
            output.seek(0)

            name = os.path.splitext(
                os.path.basename(self.profile_picture.name)
            )[0] + '.jpg'
            self.profile_picture = ContentFile(output.read(), name=name)

        super().save(*args, **kwargs)

03. Key Features

What Makes It Work

A breakdown of the most technically interesting parts of the platform.

Real-Time Chat with Link Previews

The chat system uses Django Channels with WebSockets for instant message delivery. Unlike AJAX polling, WebSockets maintain a persistent connection. To fix raw, naked-looking links, Celery background workers fetch OpenGraph metadata and generate rich link previews before the message is broadcast.

Flow
User sends message → Extract URLs →
Celery fetches OG tags → Broadcast
rich preview via WebSocket

Coin Economy & Rewards

Users earn coins through platform engagement. All coin mutations are protected by Django F() expressions and transaction.atomic() to prevent race conditions during concurrent transactions. An immutable Transaction ledger provides a full audit trail.

Reward Rules
  • • New post: +10 coins
  • • Post liked: +2 coins
  • • New follower: +5 coins
  • • Daily login: +1 coin

Relational Follow System

A dedicated Follow model with a unique_together constraint on (follower, following) prevents duplicate relationships. The system efficiently queries follower counts, following lists, and mutual connections without N+1 query problems thanks to prefetch_related and annotated counters.

Optimized Query
User.objects.prefetch_related(
'following', 'followers'
).annotate(...)

AJAX Social Interactions

Like, follow, comment, and block actions happen without page reloads. Vanilla JavaScript handles DOM updates while Django views return JSON responses. Rate limiting middleware prevents API abuse by throttling endpoints per user.

AJAX + Rate Limiting
fetch('/api/like/', {
method: 'POST',
body: JSON.stringify({post_id: id})
}).then(r => r.json())
.then(data => updateUI(data))

OAuth-Only Authentication

Authentication is handled entirely through OAuth 2.0 via GitHub and Google. No passwords are ever stored in the database, eliminating an entire class of security vulnerabilities (breaches, rainbow tables, weak passwords) and simplifying the user onboarding flow.

Providers
  • • GitHub OAuth 2.0
  • • Google OAuth 2.0
  • • Zero password storage
  • • Custom user model flexibility

Gravity-Based Feed

Instead of a simple chronological feed, posts are ranked using a gravity-based algorithm that balances engagement (likes, comments, coins earned) against time decay. High-quality posts get more airtime, but recency still matters — preventing stale content from dominating.

Gravity Score
score = (likes * 2 + comments * 3)
/ (hours_since_post + 2)^1.5

Redis Online Status

User online status is tracked in Redis with automatic TTL expiration. When a user connects via WebSocket, their presence is written to Redis. When they disconnect, it expires after a short grace period. This powers "online now" badges without database writes on every heartbeat.

Redis Pattern
SET user:123:online 1 EX 60
GET user:123:online → 1 (or nil)

Celery Background Tasks

Heavy or slow operations are offloaded to Celery workers: generating link previews, sending batch email notifications, computing gravity feed scores, and cleaning up deactivated accounts. This keeps the web workers responsive and the user experience snappy.

04. Challenges & Solutions

What Went Wrong & How I Fixed It

1

Coin Economy Race Conditions

Two users liking a post simultaneously — or a user transferring coins while receiving a reward — could result in incorrect balances due to non-atomic read-modify-write operations.

Solution:

Wrapped all coin mutations in Django's F() expressions and transaction.atomic(). This ensures atomic increments without race conditions, even under concurrent load. The Transaction model provides an immutable audit log for every mutation.

2

WebSocket Connection Drops on Mobile

Mobile browsers aggressively kill background connections. Users would lose their chat session when switching apps, requiring a full reconnection.

Solution:

Implemented a reconnection strategy with exponential backoff. The client stores the last message ID and requests a catch-up batch on reconnect, ensuring no messages are lost even after hours of disconnection.

3

Raw, Naked Links in Chat

Users pasting URLs into chat resulted in long, unstyled strings that broke the UI flow and gave no context about where the link led.

Solution:

Built a link preview pipeline using Celery. When a message contains a URL, a background task fetches the page, parses OpenGraph tags (title, description, image), and attaches the metadata before broadcasting the enriched message to all clients.

4

API Abuse & Spam

Without rate limiting, endpoints for liking, following, and coin transfers were vulnerable to bot attacks and accidental brute-force usage.

Solution:

Implemented per-user rate limiting on all sensitive API endpoints. Throttling is based on authenticated user IDs rather than IP addresses (since multiple users can share a network), with stricter limits on coin transfers and report submissions.

5

Cloudinary Storage Bloat

Users uploading high-resolution profile pictures and post images quickly consumed Cloudinary storage quota. Unoptimized 4MB JPEGs were being stored for 300px avatars.

Solution:

Overrode the User model's save() method to auto-downscale images using Pillow before they hit Cloudinary. Profile pictures are resized to 300px and compressed to 60% quality JPEG, typically reducing file size by 80-90%.

6

Chronological Feed Stagnation

A simple "newest first" feed meant that a single popular post could dominate the timeline for days, while quality niche content from smaller creators was buried within hours.

Solution:

Replaced the chronological feed with a gravity-based ranking algorithm. Each post gets a score based on engagement weighted against time decay. Celery recalculates scores periodically, ensuring the feed stays fresh and meritocratic.

7

Blocking the Request Loop

Sending welcome emails, processing link previews, and updating feed scores synchronously inside HTTP request handlers created slow responses and occasional timeouts.

Solution:

Introduced Celery with Redis as the broker. All non-critical work is now queued as background tasks: emails, OG tag fetching, gravity score recomputation, and periodic cleanup jobs. Web workers stay fast and only handle the request/response cycle.

05. Tech Stack

The Tools That Power It

Django + Python

The backbone of the application. A custom User model extending AbstractUser provides full control over authentication, economy fields, and social counters. Django's ORM handles all relational database operations.

Django Channels + WebSockets

Extends Django to handle WebSockets for real-time chat. Redis acts as the channel layer, enabling message broadcasting across multiple workers and connections.

PostgreSQL

Relational database with carefully normalized models. Proper indexing on foreign keys and denormalized counter fields ensures the follow system, gravity feed, and coin transactions remain fast at scale.

Redis

Dual-purpose: serves as the Django Channels layer backend for WebSocket message routing, and as a fast cache for online user presence tracking with automatic TTL expiration.

Celery

Background task queue for link preview generation, email notifications, gravity feed score recomputation, and media cleanup. Keeps web workers responsive by offloading heavy I/O.

Tailwind CSS + Vanilla JS

Utility-first CSS for rapid UI development. No framework bloat — just clean, semantic HTML with Tailwind classes and vanilla JavaScript for interactivity and AJAX.

Render

Hosted on Render's paid tier for zero cold-start latency and guaranteed uptime. Native WebSocket support and auto-deploy from Git make it the perfect platform for this real-time application.

Cloudinary

Cloud-based media management for profile pictures and post images. Combined with server-side downscaling, it keeps storage costs low while delivering optimized assets via CDN.

OAuth 2.0 (GitHub + Google)

Authentication is fully delegated to GitHub and Google via OAuth 2.0. No passwords are stored locally, removing an entire attack surface and streamlining onboarding.
